# 迟回复引用用户原句（验收）

用户先发「你们是谁」，再发「在干嘛」。后一句并进同一条忙着的工作线。迟回复只出现一次，引用里的原句在左边（这是 Bot 在引用历史），历史里不再留一份。发出去的那句仍在右边，一行输入是一行气泡。

群正在开口时连发「hi」和「你们是谁」也一样：两句都在这条回复旁边各留一个用户气泡，更早的历史气泡去掉。

| 验收 | 期望 |
| --- | --- |
| 同一句只出现一次 | 「你们是谁」在整段对话里只有一处 |
| 引用在左边，一行就是一行 | 「回复你更早的这句」在左边。引用里的「你们是谁啊」不在气泡里折断。右边发出去的「在干嘛呢」也没有空的第二行 |
| 历史让位 | 引用出现后，更早的历史里不再有第二句「你们是谁」 |
| 跟进也在引用里 | 并进去的「在干嘛」出现在同一条回复的引用里。群会话这条线再忙，也不是第二条工作线，两句都并进正在写的那条，不弹选择卡 |
| 不印到更早的回复上 | 引用只落在这句跟进之后的回复上。更早的另一条回答不会带上这两句 |
| 刷新还在 | 回合已经结束时，迟回复写进会话，并且不再呼叫成员。刷新后仍是一条带这两句的用户气泡引用 |
| 不另开一条群回复 | 不为「在干嘛」再开一条只属于它的群回复。别的房间里剩下的工作线，在开口时不弹选择卡，也不把这句话收走。这句话仍是群里的用户气泡 |
| 回合里的两句不重复 | 开口的转发还在跑、成员还在输入时，「hi」「你们是谁」各只出现一次。不再多出下面那对带「未读」的气泡；成员还没发言时也一样。引用画出原句之后，桌面自己画的历史气泡也去掉，不只是 `.bt-umsg` |
| 选择之后仍是一条引用 | 两条工作线都对得上时先弹卡。确认其中一条之后，迟回复的引用仍是按发送顺序的那两句 |

成员超时默认仍是 240000 毫秒。测试可以设 `DSH_ROOM_REPLY_TIMEOUT_MS` 为一个正数，不设则不变。

`cite-runtime.test.js` 把群主机跑起来：确认忙着的秋水线之后，回合已经结束时回复写进房间会话，刷新后仍是一条迟引用；更早的成语回答不会被印上这两句；同一轮后面的一段不再带第二条引用，也不呼叫成员。
